L’application [Work → Réclamations](https://agentium.papai.ai/work/reclamations/studio)
est publiée en live. La file retourne les trois dossiers depuis PostgreSQL ;
chaque dossier retourne les cinq lectures bornées, une provenance `live` en
`repeatable_read`, un hash de snapshot et six sources réellement mappées.
Les originaux et leurs passages cités sont lisibles sur place : bordereau
LM-1042, confirmation de perte LM-1043 et reçu RF-1044. Une actualisation restitue
le Run existant et son reçu.

Chaque Run a exécuté quatre décisions natives `decide_next_v1`, les lectures
appropriées, une proposition contrôlée, puis une pause à `hitl.review`.
La validation dans Work reprend l’exécution et produit exactement un reçu par
dossier, `status=simulated` et `external_payment_called=false`.
La répétition de la validation de LM-1044 retourne **409** ; son reçu reste unique.
RC-9999 retourne **404 / CLAIM_NOT_FOUND**, sans dossier de remplacement.
Les trois reçus de QA restent conservés : ne pas réinitialiser les données pour
masquer l’historique. Les trois Runs permettent de rejouer la présentation de
leurs preuves ; une nouvelle action identique reste protégée contre les doublons.

Les [preuves structurées](LIVE-EVIDENCE-2026-10-02.json) conservent les vrais IDs,
les statuts, les choix d’outils, les hashes, les sources et les reçus. Elles ne
contiennent ni session d’authentification, ni mot de passe, ni temps humain inventé.

## Présentation et corrections livrées

Sur le site : interface FR/EN, thèmes clair/sombre, desktop 1 440 px et mobile
390 px. Aucun débordement horizontal ; aucun problème axe dans les audits du
studio desktop, mobile et sombre après chargement. Les originaux se chargent
dans le dossier sélectionné. Les requêtes 404/409 ci-dessus sont des contrôles
négatifs volontaires, pas des erreurs de navigation.

Cinq défauts reproduits dans la version servie sont corrigés dans le dépôt :

1. Les motifs `delivery_disputed`, `parcel_lost`, `refund_requested` sont traduits
   dans les deux langues.
2. Le document ouvert reste sélectionné par son identité quand les citations
   arrivent et réordonnent la liste. Auparavant, ouvrir le bordereau pendant
   l’enquête pouvait afficher ensuite la procédure SAV à sa place.
3. La réponse partielle de validation conserve les preuves et la proposition
   jusqu’à l’actualisation canonique du Run. Auparavant, elles disparaissaient
   brièvement après le clic.
4. Les étapes terminées utilisent la couleur de progression ; le rouge est
   réservé aux échecs. Une règle CSS appliquait le rouge à toutes les étapes.
5. Les boutons de documents utilisent l’icône SVG native, sans carré dû à un
   caractère absent de la police du navigateur.

Les corrections ont passé : build production, compilation Angular, **1 891 tests
unitaires**, **cinq parcours Playwright**, gates i18n/navigation/chrome et contrôle
des secrets de l’index. Le nouveau parcours reproduit le réordonnancement des
citations avec deux documents distincts ; les fixtures utilisent les vrais codes
de motif et une réponse HITL partielle. Le parcours contrôle aussi la couleur des
étapes terminées dans les deux thèmes.
