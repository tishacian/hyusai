# Contrôle, transport et scaffolds natifs — supplément local

**55 tests passent en 48,52 s**, sans skip : 15 cas PostgreSQL et 40 cas d’infrastructure (dont 19 pour le candidat Temporal natif). Helm 3.17.3 rend réellement les templates. Les reapers de RecipeExecution, ML et Run disposent de transactions indépendantes ; un verrou gardé par une autre session fait annuler uniquement la transaction concernée. Les autres contrôleurs et l’outbox restent exécutables. Les erreurs PostgreSQL autres que 55P03/57014 se propagent. Les bornes 250 ms et 1 s portent sur les verrous et statements ; elles ne constituent pas un SLA global.

La migration 134 finale, incluant `execution_dispatches.reconciled_at` et son index, passe ses deux tests PostgreSQL dans ce ciblé. Le roundtrip de la chaîne tabulaire est également rejoué avec psql/Alembic réels : **1 test, 40,27 s**, upgrade → downgrade → upgrade. La recette complète précédente de 27 tests reste conservée séparément.

La recette RabbitMQ 4.1.8 et le contrôle de drainage flags fermés passent ensemble : **2 tests, 27,80 s**. L’outbox conserve l’intention pendant un arrêt réel du broker. Un envoi confirmé, suivi d’une panne injectée avant l’acquittement PostgreSQL, survit au redémarrage réel du broker ; la republication conserve le même `task_id`. La fermeture réelle de la connexion consommateur après commit natif et avant ack produit une redelivery. Trois consommations produisent une seule claim via `ml_lifecycle.start` et un seul petit effet transactionnel de fixture. Le consommateur est Kombu ; aucun entraînement ni processus worker Celery complet n’est exécuté. La panne du publisher est injectée à la frontière de confirmation, sans tuer un processus OS. Ces limites empêchent de transformer cette preuve en promesse d’effets externes exactement une fois.

L’image d’orchestration C est préparée à partir d’une image worker de même SHA vérifié et ajoute seulement le SDK Temporal 1.34.0, avec ses transitives supplémentaires épinglées hors contraintes principales. Les queues de contrôle et d’orchestration restent séparées ; les admissions sont fermées par défaut. L’image C n’a pas été construite ici, faute de base worker qualifiée disponible : aucune mesure de taille, mémoire ou qualification runtime C n’est déduite des scaffolds ni de l’image historique A/B.

Les sources, commandes, limites et empreintes figurent dans `validation.json`. Les logs ne contiennent pas de secrets ; les métadonnées Docker sont sélectionnées sans `Config.Env`. Le conteneur et l’image RabbitMQ jetables ont été supprimés après lecture de la version et des limites. PostgreSQL partagé et le serveur Temporal appartenant à l’autre recette sont conservés. Aucune VM ni configuration d’admission n’a été activée.
