# Work prediction cards

A certified `prediction` block displays one model result. It uses the existing
Work `dataBinding` (a local action's Run output) or `queryBinding` (a workspace
System binding), with the same access controls as other runtime blocks. Opening
a page does not score a model. A query is explicitly invoked by the user.

In the Work editor, add **Prediction**, select its runtime source and fill the
prediction contract. The editor exposes the model/version, task, target, class,
column mappings, units, freshness and display bands; no business-specific code
or private workspace setting is required. Drafts may remain incomplete; release
readiness rejects an invalid contract or a missing data source.

```json
{
  "type": "prediction",
  "id": "renewal-advice",
  "props": {
    "title": "Renewal likelihood",
    "dataBinding": {
      "source": "run-output",
      "componentId": "predict-renewal",
      "selector": "output"
    },
    "predictionContract": {
      "schema_version": 1,
      "model_id": "published-model-id",
      "model_version": 2,
      "task": "classification",
      "target": "will_renew",
      "positive_label": "yes",
      "label": "Probability of renewal",
      "unit": "probability",
      "value_column": "prediction",
      "score_column": "score",
      "max_age_seconds": 3600,
      "order": "ascending",
      "bands": [
        {"key": "contact", "label": "Contact the customer", "min": 0},
        {"key": "likely", "label": "Likely to renew", "min": 0.8}
      ]
    }
  }
}
```

The optional `dataBinding.nodeId` or `queryBinding.nodeId` selects the output
of an exact published node, instead of the final Run output. The advanced source
editor exposes this field. For example, `nodeId: "model.context"` with
`selector: "model_advice"` reads model evidence even when a later node produces
a receipt. Release readiness checks that the node exists in the bound published
Flow. Runtime uses only that node's latest attempt in the already-authorized
Run; a failed retry never falls back to an earlier successful score.

Use the selector appropriate to the binding's actual output schema. A native
`ml_predict_v1` output supplies `served`, `task`, `target`, `positive_label`,
`captured_at` and one item in `predictions`. The card rejects multiple rows rather
than choosing a record silently. The native service records `captured_at` when
it produces the answer, independently of when Work opens it.

A backend that reads an authorized scored dataset can use
`work_predictions.project_row` to produce a canonical envelope containing
`schema_version`, `status`, `model`, `task`, `target`, `positive_label`, `unit`,
`value`, `score`, `interval`, `captured_at` and `provenance`. Model and dataset
links preserve the drill-down. `project_row` does not fetch data or replace
workspace authorization. Its caller validates model lineage before projecting.
`validate_dataset_contract` checks the model pin, target, positive class and
that every mapped prediction column was actually generated by scoring. New
scored datasets carry an explicit `prediction_output` column map in lineage;
this prevents a same-named input column from being displayed as a model score.
Legacy artifacts are accepted only with proven generated standard column names.

| Task | Required semantics | Rendering |
| --- | --- | --- |
| Classification | Target, positive class, probability column, `unit: probability` | Probability of the declared class; winning-class confidence is never substituted |
| Regression | Target, value column, explicit unit | Numeric value; optional paired lower/upper columns whose bounds contain the value |
| Clustering | Value column, `unit: segment`, `order: none`, no bands | Version-specific segment identifier, without probability or rank |

Display bands have inclusive minimums. Their labels, keys and minimums are
unique; the applicable band has the greatest minimum not exceeding the value.
They do not change the trained decision threshold. A regression interval is a
prediction interval, not an amount of human effort or a financial saving.

Model ID, version, target and positive class must match the authored contract.
Invalid, missing, future-dated or expired evidence is unavailable; the component
rechecks its age while the page remains open. It does not show a stale score as
current advice. A historical result remains available through the model/Run
screens.

The existing claims facade consumes the same contract for classification and
keeps its historical queue payload fields for compatibility. Its former SLA
constants now serve only to migrate older installations without an authored
contract. New activation configurations persist that contract explicitly.
