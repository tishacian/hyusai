# Machine learning plane (no-code sklearn training, MLflow format + registry)
# - pandas: the frame sklearn and skrub are fit on (polars is the storage side)
# - skrub: automatic preprocessing of heterogeneous columns, so "no-code" means
#   no feature engineering rather than numeric-only datasets
# - skore: the evaluation engine, from the scikit-learn maintainers. One report
#   per fit caches its predictions, so the metric table, the ROC, the PR curve,
#   the confusion matrix and the permutation importances are one pass over the
#   test split; it also reports log_loss and brier_score, which say whether a
#   probability is calibrated rather than merely ranked. Pulls matplotlib and
#   plotly as its display layer; we read the tidy .frame() and chart in the
#   browser, so nothing renders server side
# - mlflow (NOT mlflow-skinny): the MLmodel format, the pyfunc loader, AND the
#   SQL-backed Model Registry. Skinny omits the SQL stores, and a SQL store is
#   the only kind that supports a registry — a bare mlruns/ file store raises on
#   create_registered_model. No MLflow *server* is operated: the client writes
#   straight to a `mlflow` database on the Postgres instance already running
# - skops: how the pipeline is serialized. Unlike pickle it refuses to
#   reconstruct a type that was not declared trusted when the model was saved
# - boto3: the whole promise of storing models in MLflow format is that a client
#   we did not write can load them. On MinIO the registry's `source` is an
#   `s3://` URI, and mlflow's S3 artifact repository imports boto3 by name —
#   botocore, which s3fs already brings for our own reads, is not enough. Absent
#   it, `mlflow.pyfunc.load_model(version.source)` raises ModuleNotFoundError on
#   the deployed object store while passing on a local one, which is the worst
#   shape a portability claim can have.
